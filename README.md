# Сайт-портфолио разработчика

Статический сайт на **Astro 7 + TypeScript + Tailwind CSS 4**. Публикуется бесплатно на **GitHub Pages** через GitHub Actions. Серверной части и базы данных нет.

Всё, что вы редактируете (тексты, проекты, изображения), лежит в отдельных файлах. Компоненты и CSS менять не нужно.

## Где что лежит

```
├── src/
│   ├── data/
│   │   ├── profile.ts        ← имя, профессия, описание, контакты, ссылки, SEO
│   │   ├── skills.ts         ← навыки и категории
│   │   ├── experience.ts     ← опыт и образование (необязательно)
│   │   └── ui.ts             ← тексты интерфейса (кнопки, заголовки разделов)
│   ├── content/projects/     ← ОДИН .md-файл = ОДИН проект
│   ├── styles/global.css     ← цветовая палитра (переменные в начале файла)
│   ├── content.config.ts     ← схема полей проекта (проверка при сборке)
│   ├── components/ layouts/ pages/ lib/   ← код сайта (трогать не нужно)
├── src/assets/images/        ← аватар, обложки и скриншоты проектов (сжимаются при сборке)
├── public/
│   ├── images/               ← файлы «как есть»: картинка для соцсетей, картинки внутри текста проекта
│   └── favicon.svg           ← значок сайта
├── astro.config.mjs          ← адрес сайта (site) и подпапка (base) для GitHub Pages
├── scripts/check-site.mjs    ← проверка ссылок и заглушек после сборки
└── .github/workflows/deploy.yml  ← автоматическая публикация
```

## Запуск локально

Нужен [Node.js](https://nodejs.org/) версии 22.22 или новее.

```bash
npm install        # один раз, устанавливает зависимости
npm run dev        # сайт на http://localhost:4321 с автообновлением
```

Другие команды:

| Команда | Что делает |
| --- | --- |
| `npm run typecheck` | проверяет TypeScript и поля проектов |
| `npm run build` | собирает сайт в папку `dist/` |
| `npm run preview` | открывает собранный сайт локально |
| `npm run check` | проверка типов + сборка + проверка ссылок и заглушек |

В режиме `npm run dev` видны проекты-черновики (с пометкой «Черновик»). На опубликованном сайте их нет.

## Как изменить имя, описание и контакты

Откройте `src/data/profile.ts` и замените значения: `name`, `role`, `tagline` (Hero), `about` (абзацы раздела «Обо мне»), `specialization`, `location`, `availability`, `email`, `socials`.

- Ссылка на соцсеть: добавьте или удалите строку вида `{ label: 'GitHub', url: 'https://github.com/ваш-ник' }`.
- Необязательные поля (`location`, `availability`, `resume`, `ogImage`) можно удалить: блок исчезнет.
- Резюме: положите PDF в `public/` (например, `public/resume.pdf`) и добавьте
  `resume: { label: 'Скачать резюме', url: '/resume.pdf' }`.
- Тексты кнопок и заголовков разделов находятся в `src/data/ui.ts`.
- Язык страницы задаёт поле `lang` в `profile.ts`.

Навыки редактируются в `src/data/skills.ts`, опыт и образование — в `src/data/experience.ts`. Если оба массива опыта и образования пустые, раздел скрывается.

## Как поменять аватар

1. Положите фото в `src/assets/images/` (квадратное, от 600×600 пикселей; JPG, PNG или WebP). Сжимать вручную не нужно.
2. В `src/data/profile.ts` укажите путь относительно этой папки: `avatar: 'avatar.jpg'`.
3. Обновите `avatarAlt`: короткое описание фото для экранных дикторов.

Если файла нет, на его месте показываются инициалы из имени.

## Проекты

Каждый проект — отдельный файл в `src/content/projects/`. Имя файла становится адресом страницы: `my-app.md` → `/projects/my-app/`.

### Добавить проект

1. Скопируйте любой существующий файл в `src/content/projects/` (например, `idle-deepminer.md`) под новым именем, например `my-app.md`.
2. Заполните поля в начале файла (между строками `---`).
3. Положите изображения в `src/assets/images/projects/my-app/` и укажите пути в `cover` и `gallery` (относительно `src/assets/images/`).
4. Сохраните. Компоненты редактировать не нужно.

Пример:

```md
---
title: "Мой проект"
summary: "Одно-два предложения о проекте."
date: 2025-03-01
order: 1
featured: true
cover: projects/my-app/cover.png
coverAlt: "Главный экран приложения"
gallery:
  - src: projects/my-app/screen-1.png
    alt: "Страница настроек"
    caption: "Необязательная подпись"
technologies: ["TypeScript", "Astro"]
role: "Разработчик"
status: "Завершён"
links:
  demo: "https://example.com"
  repo: "https://github.com/ваш-ник/my-app"
problem: |
  Какую задачу нужно было решить.
solution: |
  Что и как вы сделали.
---

Дополнительный текст в формате Markdown: результаты, выводы, список.
```

### Поля проекта

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `title` | да | Название |
| `summary` | да | Краткое описание, до 220 символов |
| `date` | нет | Дата в формате `ГГГГ-ММ-ДД`: показывает год и сортирует проекты с одинаковым `order` |
| `order` | нет | Порядок: меньше число — выше в списке (по умолчанию 100) |
| `featured` | нет | `true` — показывать на главной. Если ни один проект не отмечен, на главной показываются все |
| `draft` | нет | `true` — скрыть проект на опубликованном сайте |
| `cover`, `coverAlt` | нет | Обложка (путь относительно `src/assets/images/`) и её описание |
| `gallery` | нет | Список изображений: `src`, `alt`, `caption` |
| `technologies` | нет | Список технологий |
| `role`, `status` | нет | Ваша роль и статус проекта |
| `links.demo`, `links.repo` | нет | Ссылки (полные адреса с `https://`). Кнопки появляются только если ссылка указана |
| `problem`, `solution` | нет | Задача и решение; абзацы разделяйте пустой строкой |

Если поле заполнено неправильно (например, некорректная ссылка), сборка остановится и подскажет, что исправить. Если указанного файла картинки нет, сайт покажет заглушку, а в консоли появится строка `[images] Файл не найден: …` с путём.

### Изменить порядок, скрыть, выделить

- **Порядок:** меняйте `order`. Проекты с одинаковым `order` сортируются по дате, новые выше.
- **Скрыть:** `draft: true`. Чтобы вернуть, поставьте `false` или удалите строку.
- **Выделить на главной:** `featured: true`. Остальные проекты остаются на странице «Все проекты».

### Редактировать и удалить проект

- Редактирование: откройте файл проекта, измените поля или текст.
- Удаление: удалите файл `.md` и, если не нужна, папку с картинками в `src/assets/images/projects/`.

## Изображения

- Обложки, скриншоты и аватар кладите в `src/assets/images/`. При сборке Astro сам переводит их в WebP, делает несколько размеров для разных экранов и задаёт размеры, чтобы страница не «прыгала» при загрузке. Исходники можно загружать как есть, например PNG-скриншоты любого размера.
- **Заменить изображение:** положите новый файл с тем же именем поверх старого либо загрузите файл с другим именем и поправьте путь в файле проекта.
- Если файл не найден, сайт показывает аккуратную заглушку, а не битую картинку.
- Картинка для превью в соцсетях у проекта делается из его обложки автоматически (1200×630, JPG). Для главной страницы положите PNG или JPG 1200×630 в `public/images/` и укажите `ogImage: '/images/og.png'` в `profile.ts`.
- Картинки внутри текста проекта (`![Описание](/images/projects/my-app/screen.png)`) и другие файлы в `public/` не обрабатываются: перед загрузкой уменьшите их сами (ширина до 1600 пикселей, WebP или JPG). Команда `npm run check` предупредит о файлах тяжелее 300 КБ.

## Скорость загрузки

Что уже сделано, делать ничего не нужно:

- вся страница отдаётся готовым HTML, JavaScript на сайте около 2,5 КБ;
- стили встроены в HTML, отдельного запроса за CSS нет;
- подключено только два подмножества шрифта (кириллица и латиница, около 50 КБ), оба загружаются с предзагрузкой;
- изображения сжимаются, переводятся в WebP, подгружаются по мере прокрутки (главная картинка страницы грузится сразу и с приоритетом);
- страница проекта подгружается заранее, когда курсор наведён на ссылку.

## Цветовая палитра

Откройте `src/styles/global.css`. В начале файла две группы переменных: `:root` (светлая тема) и `[data-theme='dark']` (тёмная). Меняйте HEX-значения:

| Переменная | Для чего |
| --- | --- |
| `--bg` | фон страницы |
| `--surface` | фон карточек |
| `--ink` | основной текст |
| `--muted` | второстепенный текст |
| `--line` | границы |
| `--accent` | ссылки, фокус, акценты |
| `--accent-ink` | текст на фоне акцента |
| `--accent-soft` | фон тегов |

Подберите значения так, чтобы контраст текста с фоном был не ниже 4,5:1 (проверка: [webaim.org/resources/contrastchecker](https://webaim.org/resources/contrastchecker/)). Тема переключается кнопкой в шапке и запоминается; по умолчанию используется системная.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub (например, `portfolio`) и загрузите в него проект:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/ВАШ-НИК/portfolio.git
   git push -u origin main
   ```
2. На GitHub откройте **Settings → Pages**. В поле **Source** выберите **GitHub Actions**.
3. Откройте вкладку **Actions**. Первый запуск стартует после `push` в `main` (если нет, запустите workflow вручную через **Run workflow**).
4. Когда workflow станет зелёным, сайт будет доступен по адресу `https://ВАШ-НИК.github.io/portfolio/`.

Адрес и подпапка (`site` и `base`) определяются автоматически из имени репозитория:

| Репозиторий | Адрес сайта |
| --- | --- |
| `ВАШ-НИК/portfolio` | `https://ВАШ-НИК.github.io/portfolio/` |
| `ВАШ-НИК/ВАШ-НИК.github.io` | `https://ВАШ-НИК.github.io/` |

Менять `astro.config.mjs` не нужно, даже если вы назвали репозиторий иначе. Свой домен: задайте переменные `SITE_URL` (например, `https://example.com`) и `BASE_PATH` (`/`) в шаге **Build** файла `.github/workflows/deploy.yml` и укажите домен в Settings → Pages.

Каждое изменение дальше публикуется само:

```bash
git add .
git commit -m "Добавил новый проект"
git push
```

Секретные токены не нужны: workflow использует только встроенные права GitHub Actions.

## Если сборка падает

- **Ошибка в поле проекта** (`does not match collection schema`): в сообщении указано поле и причина; исправьте файл проекта.
- **Страницы без стилей или картинок после публикации:** проверьте, что в Settings → Pages выбран источник **GitHub Actions**, а пути к картинкам в проектах начинаются с `/images/`.
- **Предупреждения `Осталась заглушка`** после `npm run check` показывают, что в данных остались примеры (`USERNAME`, `example.com`). Это не ошибка, но перед публикацией замените их.

## Подключение визуальной CMS в будущем

Контент уже хранится в виде файлов с типизированными полями: Markdown и front matter для проектов, изображения в `src/assets/images/`. Такую структуру понимают Git-ориентированные CMS (например, Keystatic, Decap CMS, TinaCMS): им достаточно описать те же поля и папки, а компоненты менять не придётся. Сейчас никакой CMS в проект не добавлено.
